## 关键行为证据

- 测试相机通过真实 `getUserMedia` 与 `MediaRecorder` 生成照片/录像；它仅在测试进程启动参数中启用，产品没有模拟摄像头开关。
- 模拟上传已经在服务端成功、响应在客户端丢失：页面显示未保存，重试复用拍摄编号，服务端保留一份原始文件和一个素材版本增量。
- 完整停止并重建 Node 服务后，原始图片、草稿、复查记录及有效会话可继续读取。
- 跨账号读取草稿、媒体、检查与报告被拒绝；核验端点只接收模拟场景、三项资料齐备标记与核验版本，带图片或个人资料的请求被拒绝。旧 `/api/identity-mock` 返回 410，不能绕过房产证要求。
- 未核验、模拟失败或重新核验后，10 类主线写入（含素材上传、复查确认、重建与实时指导）被服务端拒绝，平台桩调用计数为 0；已有草稿、素材与配置仍可读取。
- 旧版仅身份证通过的账号不获新准入；三项通过状态重启后保留，重置后旧页面提交被拒绝。
- 核验在异步复查中被撤销时，复查结果不写入；采集上传被拦后，页面保留未保存图片，核验通过后恢复并保存一份素材。
- 新增的账号核验契约测试先在旧实现下失败；服务端实现后通过。浏览器断言核验不占主线步骤，主线只保留三步，身份证/房产证图片没有网络上传。
- 补拍和移除素材会使人工确认失效；旧复查仍可追溯，但不能继续确认当前版本。
- 服务端在付费创建连接丢失后保留 UNKNOWN；重复创建返回冲突，适配器创建计数保持 1。
- 平台返回成功但没有 SPZ/PLY 时保持 ASSET_MISSING；不会显示成果可用或验收通过。
- 实际加载的是既有工作台 SPZ 文件，并操作视角重置；视觉质量仍如历史试验所述存在明显缺陷。
