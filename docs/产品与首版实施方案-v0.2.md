## 1. 产品定位与范围

房东希望通过现场拍摄还原房屋空间，帮助后续远程看房，同时记录设施与房屋现状。当前先解决一次采集能否顺利完成：拍摄时知道怎么拍，离开后能够继续，拍完后知道哪里需要补充。

**产品定义：面向房东的房屋采集与三维预览工具，提供简单登录、用户中心证件核验与采集准入、实时拍摄、素材暂存、Agent 指导和重建结果检查。**

远程看房仍是主要业务用途，首版只覆盖房东侧采集、指导、内部预览和确认，不建设租客端。

### 当前首版范围

保留简单登录、用户中心身份证与房产证核验 Mock、最小房屋与房间信息、现场拍摄、采集草稿、两种 Agent 指导、重建任务状态、内部三维预览、实拍对照和成果下载。

房屋名称、房间名称等信息仅用于区分本次采集。查看和恢复自己的采集草稿属于核心流程，不扩展为完整房源管理后台。

暂不做账号注册与邀请管理、完整个人资料编辑、改密与找回密码页面、账号停用管理、用户与角色管理、房源列表的完整增删改查、出租状态管理、归档与检索后台、运营统计或系统配置中心。真实身份及房屋权属核验服务也不在本次 Mock 范围内。

继续排除租客账号与页面、公开分享和发布、预约咨询、合同支付、租金账单、完整维修工单、多组织协作。首版不承诺整屋自动拼接、自动户型图、精确测量或设施故障诊断。

## 2. 简单登录与用户中心核验

### 2.1 简单登录

后续首版只提供账号与密码登录、退出、会话过期后重新登录。账号可采用预置测试账号，暂不建设账号管理页面；开通方式在正式实施前确定。

简化页面不等于取消基本保护。真实接入后，密码与服务凭据仍不能明文泄露，服务端仍需校验会话和素材归属。当前方案不以模拟登录代替真实认证，也不要求为了这些规则先建立完整管理后台。

### 2.2 用户中心：身份证与房产证核验 Mock

证件核验属于账号准备，不放在采集主线步骤中。登录后可以查看“我的采集”和独立重建样例；未通过时由新建/继续入口引导至用户中心，不能推进采集。

用户中心只展示当前账号、核验状态和必要的证件操作，不扩展完整管理后台。资料包括身份证人像面、国徽面、房产证，三项缺一不可。通过后显示“已通过 · Mock”；状态跟随账号保存，后续采集无需反复核验。旧版仅身份证通过的账号须补做三项核验。

本轮使用示例或本地测试图片，图片仅在用户中心临时预览；通过、离开或退出后清除。服务端只保存模拟状态、检查场景和时间，不接收图片或个人资料。房产证采用账号级 Mock，不证明任何具体房屋的权属，也不与每套房源建立权属绑定。

| 状态或操作 | 反馈与准入 |
| --- | --- |
| 未核验/缺少任一证件 | 提示补齐三项资料；主线不可推进 |
| 三项已选择 | 可预览、替换、移除后提交模拟核验 |
| 文件格式不支持、超限或无法读取 | 指出对应图片的问题，不沿用旧通过结果 |
| 核验中 | 显示处理中，阻止重复提交和并行修改 |
| 模拟通过 | 标注“已通过 · Mock”，返回我的采集后可新建或继续 |
| 模拟反光、身份证缺边角、房产证信息页缺失 | 显示未通过，明确对应资料；更正后重新提交 |
| 核验服务失败或请求中断 | 不默认通过，保留重试入口 |
| 通过后重新核验 | 立即暂停采集权限，再次通过后恢复；已有草稿保留 |
| 刷新、重新登录或重启服务 | 恢复账号核验状态；临时证件图片不恢复 |

客户端入口和服务端主线写入同时检查核验状态，包括新建、素材保存、复查/确认、重建提交与后续写入。直接请求接口不能绕过准入；核验在异步复查期间失效，也不能将结果写回推进流程。已有记录与报告可只读访问，已被外部平台受理的任务不因重新核验而自动撤销。

若保存素材时核验失效，素材保留在当前页面内存，用户中心核验通过后继续保存。重新核验不会删除已有草稿；未保存期间不得刷新或关闭页面。

本轮不做真实 OCR、人证比对、证件真伪判断、公安数据核验或房屋权属核验。“只能实时拍摄”的约束用于房屋采集，证件暂按上传预览 Mock 体验，真实认证服务另行接入。

## 3. 实时拍摄与素材暂存

### 3.1 主流程

**准入前提：登录账号已在用户中心通过身份证与房产证 Mock 核验。**

**主线步骤：现场采集 → 拍后复查 → 空间成果。**

新建时填写房屋与房间信息，实时拍照/录像并接收弹幕指导；可暂存，拍后二次指导后补拍或确认素材，再进入重建、内部预览与质检及下载。

用户中心证件核验在当前阶段只验证交互与准入，不能作为真实身份或房屋权属已核验的凭据。拍摄指导也不等于重建结果已通过验收。

### 3.2 素材只能实时拍摄

房屋重建素材、检查照片和设施近照均通过产品内相机实时采集。不提供系统相册导入、历史文件上传或拖入文件入口。需要补拍时，回到实时拍摄页面继续采集。

用户可以暂停、结束或重新拍摄。未获得相机权限、设备没有相机或相机被占用时，说明原因并提供重试指引，不自动改为相册导入。

现场采集优先验证普通视频方案，保留产品内逐张拍照的方案空间；两者都必须来自实时相机，具体首版采用视频、照片还是两者并存，实施前再确定。若采用 Aholo 多图重建，至少 20 张是接口门槛，不是房间覆盖或质量通过标准。[S1]

实时相机入口只能约束产品内的采集方式，不能单凭这一点证明素材来自特定房屋、特定时间或真实房东。当前不承诺防翻拍、定位核验或防虚拟摄像头能力。

### 3.3 拍摄后可以暂存

“暂存”是保存本产品已实时拍到的素材和采集进度，便于稍后恢复；恢复草稿不属于导入历史相册素材。

| 操作 | 拟定行为 |
| --- | --- |
| 拍摄过程中暂停 | 保留已完成的采集内容；恢复拍摄时继续当前房间 |
| 暂存本次采集 | 保存已经拍摄完成的素材、所属房屋与房间、拍摄时间和待补拍项 |
| 返回采集草稿 | 展示上次进度，允许继续拍摄、查看已有素材或进入二次指导 |
| 离开前仍有未保存素材 | 提示保存或明确放弃，不静默丢失 |
| 暂存失败或空间不足 | 明确提示失败，不显示“已保存”，保留可重试状态 |
| 恢复后提交重建 | 使用选定的草稿素材版本；再次确认后才创建重建任务 |

草稿不保存身份证或房产证图片。拍摄素材与指导记录关联当前账号和本次采集；补拍素材继续关联对应房间。

原型阶段建议先验证同设备暂存与恢复，并明确提示存储位置和保留限制。正式草稿采用本机存储还是服务端存储、是否跨设备恢复、保留多久，仍是待确定项，不能提前承诺跨设备可用。

## 4. 两种 Agent 指导方式

Agent 的目标是帮助房东得到更可用的拍摄素材。两种指导共用本次房间和采集进度，但发生在不同时间，反馈形式也不同。

| 方式 | 触发时机 | 房东看到什么 | 主要作用 |
| --- | --- | --- | --- |
| 实时弹幕指导 | 实时相机开启、拍摄进行中 | 叠加在拍摄画面上的短句 | 及时提醒拍摄动作，减少可以当场避免的问题 |
| 拍后二次指导 | 用户结束拍摄或恢复草稿后主动检查 | 问题清单、关联素材和补拍建议 | 系统回看已有素材，决定哪些位置还需要补充 |

### 4.1 实时弹幕指导

弹幕内容应简短、可执行，例如“移动慢一点”“窗边有反光，稍微换个角度”“继续拍到墙角”“保持相邻画面有重叠”。

弹幕避开主要取景区域、录制状态和操作按钮；按重要程度控制出现频率，同类提醒合并，避免连续刷屏。用户可暂时关闭弹幕，保留常驻的简短拍摄要点。需要补拍的位置可以进入拍后清单。

Agent 基于当前相机画面和本次采集进度提出建议。尚未拍到的区域不能被判断为已覆盖；看不清或无法判断时，说明信息不足，不用肯定语气声称检查通过。

后续 Mock 使用预设弹幕演示出现位置、频率和关闭行为，并明确标注“模拟指导”。预设文案不能被描述为 Agent 已经识别了当前真实画面。真实视觉服务的调用频率、延迟、费用和稳定性需另行验证。

### 4.2 拍后二次指导

用户选择“结束拍摄并检查”，或从草稿进入检查。Agent 对已经采集的照片或视频片段回看，按问题给出反馈，而不是只给一个总分。

每条建议至少包含：对应房间与素材、问题说明、可见证据或信息不足原因、建议动作、当前处理状态。

| 示例问题 | 二次指导示例 |
| --- | --- |
| 局部模糊 | “这段画面中的衣柜把手不清楚，建议停稳后补拍近照。” |
| 反光或曝光问题 | “窗边细节难以辨认，建议换一个角度补拍。” |
| 视角或连续性不足 | “现有素材不足以确认右侧墙角，请补拍相邻视角。” |
| 无法比较或判断 | 明确标记无法判断，不直接记为没有问题 |

用户可选择“按建议补拍”“补充实拍说明”或“暂不处理并注明原因”。选择补拍时回到实时相机，显示当前需要补充的位置；完成后将新素材加入同一采集草稿，再进行检查。

点击“已处理”只是用户处理记录，不能自动证明画面质量已改善。复查结论需依据新素材；服务失败或没有完成检查时，保留“待检查”状态。

### 4.3 与重建后质检的区别

这两种 Agent 指导主要服务于拍摄与素材准备。重建后的实拍和渲染对照仍保留，用来发现重建产生的失真、缺失或模糊。

重建前的素材检查通过不保证三维结果合格，拍后指导也不能从未拍到的内容中补造房屋现状。

## 5. 页面与浅色界面

页面围绕一次采集组织，不采用完整管理后台的菜单结构。

| 页面或步骤 | 核心内容 |
| --- | --- |
| 简单登录 | 账号、密码、错误提示和退出入口 |
| 用户中心（独立于采集主线） | 账号摘要、身份证两面与房产证入口、模拟核验、通过标记与重新核验 |
| 开始或恢复采集 | 必要的房屋与房间信息、自己的采集草稿 |
| 现场拍摄 | 实时画面、拍摄控制、弹幕开关、当前补拍目标、暂存入口 |
| 拍后二次指导 | 已拍素材、问题清单、证据、补拍和确认入口 |
| 重建与预览 | 任务状态、三维画面、实拍对照和成果下载 |

采用浅色背景、白色内容区域、清晰的深色正文和克制的蓝色强调色。状态同时用文字和颜色表达，主操作突出，减少装饰与大面积深色后台外观。

拍摄画面保留真实影像的原始明暗，不为了浅色风格改变相机画面。弹幕使用保证可读性的底色与文字，对复杂背景也能看清；重要提示不依赖短暂动画，关闭动态效果后仍能阅读。

优先考虑手机拍摄时的单手操作、取景空间和按钮触达。桌面页面用于方案演示、素材检查和三维预览；是否支持桌面摄像头采集在实施时确定。

## 6. 三维重建与结果质检

### 6.1 重建与内部预览

Aholo 世界重建继续作为首个候选，支持多图、普通视频和 Insta360 输入。[S1] 服务支持某种输入，不代表本产品开放对应文件导入；首版仍遵守产品内实时采集规则。

按房间提交重建和切换预览。独立房间不默认拥有一致坐标、方向和尺度，不计算跨房间距离。Aholo Viewer 作为浏览器候选，资产格式、加载策略和手机性能仍需实测。[S3]

保留房间切换、预设观察点、旋转、受限移动、视角重置和细节近照。移动范围依据实际采集覆盖和输出质量确定。

### 6.2 实拍对照与辅助质检

重建后选择未参与重建的检查照片和重要局部近照，对照相应房间、版本和观察位置的渲染画面。检查照片同样通过实时相机额外采集，不能只把相邻视频帧的相似性当作独立验证。

能可靠匹配相机时做同视角对照；只能近似匹配时，只判断可对照区域；无法对应时标记无法比较。视觉模型指出疑似问题、解释证据和建议补拍，房东最终复核。

问题分为疑似重建问题、实拍中可见现状、素材不足、无法比较。输出保留位置、类别、实拍与渲染证据、影响、建议操作、不确定原因和人工处理结果。

视觉模型可能误判小图和低质量细节，视频抽帧也可能遗漏短暂内容；不能以模型自报置信度自动验收。[S4][S5] 真实接入前仍需用人工标注样本评估漏检、误报、证据定位和费用，将提示词调整样本与最终评估样本分开。

### 6.3 现状、版本与成果

设施型号、插座和局部破损通过实时拍摄的高清近照补充；尺寸由房东录入实测值并注明来源，设备运行状态由房东确认。未拍到的位置保留缺失说明，不把生成式补全作为真实现状。

每次重新重建建立独立版本，关联素材、任务、模型和检查记录。标记与报告绑定具体版本，换模型后重新确认位置和结论；保留必要的追溯信息，但暂不扩展为复杂版本管理后台。

可以下载选定模型、近照、房屋说明和检查报告。内部维护备注默认不加入展示用途导出，未验收成果仍保留“待复核”或“需补拍”等状态。下载文件不等于交付完整看房应用。

### 6.4 已有试验的边界

本次会话已用 35 张工作台照片完成一次 Aholo 极速预览重建，约 4 分钟，取得可加载的 PLY/SPZ 文件。API 链路已跑通，但实际预览存在模糊、拖影、漂浮伪影和局部色块，尚不适合正式看房展示。[S6]

该样本为展厅工作台，素材来自既有照片，用于此前单次服务验证；它不符合本轮拟定的产品内实时采集流程，也不能证明真实房间、整屋看房或 Agent 指导质量已通过验收。

## 7. 异常处理与数据边界

| 情况 | 拟定行为 |
| --- | --- |
| 登录失败或过期 | 给出明确提示；恢复登录后按权限访问自己的采集内容 |
| 证件核验 Mock 中断或未通过 | 用户中心保留重试与重新选择入口；不得推进采集主线，不删除已有草稿 |
| 拒绝相机权限、相机占用或中断 | 提示恢复方法；不转为相册导入，已完成素材按保存状态保留 |
| 草稿保存失败、空间不足或网络中断 | 显示真实保存结果，不把内存中的素材冒充已持久保存 |
| 实时 Agent 延迟或不可用 | 标记指导暂不可用，允许继续拍摄；静态拍摄要点不能伪装成实时分析 |
| 二次指导失败或素材不足 | 保留待检查或无法判断，提供重试与人工检查 |
| 重建请求超时 | 先核对任务是否存在，状态不明时不盲目重复创建付费任务 |
| 重建成功但资产缺失、损坏或无法加载 | 保持待处理，不标记可用或验收通过 |
| 页面离开时任务仍在执行 | 保留任务标识与处理结果，回来后查询原任务 |
| 补拍、替换素材或更新模型 | 重新检查对应素材或模型版本，不沿用旧通过结论 |

重复点击不能触发多个同类付费任务。补拍后重新重建应说明新增成本或配额影响，由用户确认后提交。

真实接入后，采集内容、草稿、指导结果、任务、模型和下载均校验当前账号归属；客户端隐藏入口不能代替服务端权限。身份证/房产证 Mock 与房屋采集素材分开处理，前者不进入重建或视觉指导输入。

仅要求建立支持核心流程的后端与存储，不要求同步交付管理后台。具体实现技术、存储位置和部署方式在批准进入开发后再选择。

## 8. 后续实施顺序与验收

**下表保留原阶段规划。收到“开始据此构建最小 MVP 系统”后，已实现登录、用户中心证件 Mock 与准入限制、实时采集与草稿、两种本地基础指导和可选服务适配器。真实 Agent、真实房屋与新重建效果仍待接入验收。**

| 阶段 | 拟定工作 | 评审或验收重点 |
| --- | --- | --- |
| A：确认当前方案 | 收敛页面、输入来源、暂存边界和指导方式 | 当前五项调整一致，无完整后台范围回流 |
| B：制作流程 Mock | 简单登录、用户中心三项证件核验与准入、浅色界面、两种指导的模拟反馈 | 步骤可理解，异常可恢复，模拟结果不冒充真实能力 |
| C：接入实时采集与草稿 | 相机权限、实时采集、暂存和恢复 | 不提供相册导入，保存失败不误报，恢复后可继续拍摄 |
| D：接入 Agent 与重建 | 真实弹幕指导、二次指导、异步重建、内部预览与实拍对照 | 指导有依据，任务可追溯，真实样本效果和费用有记录 |

后续重点检查：

- 简单登录与退出可用，错误和会话过期有明确处理；无注册、角色或运营管理后台。
- 用户中心 Mock 覆盖身份证缺面、缺房产证、替换、移除、无效文件、处理中、失败和模拟通过；重新核验/更换资料使原结果失效。
- 证件核验不出现在三步采集主线中；未通过时页面与接口均限制推进，通过标记刷新后保留。
- 身份证与房产证示例不含真实信息，界面不把 Mock 标为真实身份核验。
- 房屋素材只从实时相机采集，草稿恢复不增加相册导入入口；补拍也遵循同一规则。
- 已拍素材可以暂存和恢复；不能恢复未成功保存的内容，暂存范围和限制对用户可见。
- 实时指导以弹幕呈现，可关闭、不遮挡取景与按钮；服务不可用不会伪装成仍在分析。
- 二次指导关联具体素材与建议动作，能回到相机补拍；处理状态与复查结论分开。
- 浅色界面、正文对比度、手机按钮与状态反馈满足实际使用；尚未测量的项目不写“通过”。
- 真实接入后验证账号与素材隔离、重复提交保护、任务状态恢复、资产可加载、质检证据和成果版本一致。
- 实际房屋样本仍需验证采集难度、重建质量、指导效果、手机预览性能和费用。此次工作台试验不替代房屋验收。
