## 1. 产品定位与决策状态

租客依靠零散照片和视频判断房源时，难以理解空间关系，也容易遗漏设施和局部情况；房东需要反复讲解、带看，并在相册和聊天记录中寻找房屋资料。这是本方案要验证的用户问题，目前尚未完成用户访谈或量化收益测试。

**产品定义：房东用手机拍摄，建立一份可查看、可补充细节、可分享的三维房源档案，让租客远程了解房屋，同时帮助房东记录房屋现状。**

首版解决“拍好一套房、看清一套房、分享一套房”。

| 决策状态 | 内容 |
| --- | --- |
| 用户已明确 | 产品为房东端；通过拍摄还原房屋三维场景；同时服务远程看房和房东查看、记录现状，以远程看房为主 |
| 本版建议 | 3D 场景结合高清实拍；按房间重建和切换；采用现有重建服务；接入一个视觉模型辅助质检；房东确认后发布 |
| 待验证 | 真实房屋重建效果、拍摄难度、手机性能、视觉模型漏检与误报、处理时间、费用、服务使用条件 |

新建仓库目前为空应用工程，本次增加方案文档。本地“空间智能”目录中的资料和实验计划属于研究基础；现有记录不构成真实房屋重建、视觉质检或产品可用性的证明。

## 2. 用户与使用场景

首批目标用户假设为自行出租住宅、可以进入房屋拍摄并维护房源信息的个人房东。租客通过房东分享的页面看房，首版无需创建租客账号。多人协作的中介和公寓运营方暂作为后续用户研究对象。

| 场景 | 用户希望完成的事情 | 首版提供的帮助 |
| --- | --- | --- |
| 发布新房源 | 房东拍摄房屋，把房源发给潜在租客 | 按房间拍摄、生成三维展示、分享链接 |
| 远程了解房屋 | 租客看卧室布局、收纳空间、厨房和卫生间 | 切换房间、观察不同视角、点击细节照片 |
| 查看关键设施 | 租客确认空调、热水器等设施的外观与说明 | 设施标记、实拍近照、房东填写的信息 |
| 维护房屋资料 | 房东记录墙面情况、设备更换和维修事项 | 带位置和日期的私人记录 |

共同需求是：把房屋的位置关系、可见细节和相关说明放在一起，减少来回查找与重复解释。能否减少线下带看，需要后续使用验证。

## 3. 核心概念与使用流程

### 3.1 用户看到的四个概念

| 概念 | 定义与理解方式 | 用户可以做什么 |
| --- | --- | --- |
| 房源档案 | 一套房屋的资料夹 | 保存基本信息、房间、展示内容和记录 |
| 房间 | 房源档案中对应卧室、客厅等区域的一页 | 拍摄、查看三维场景、检查效果和补拍 |
| 细节标记 | 贴在房间某个位置的说明便签 | 打开设施近照、文字说明或私人记录 |
| 看房分享页 | 房东确认后交给租客的一份展示版本 | 看房、切换房间、查看公开细节 |

### 3.2 完整流程

1. **创建房源**：填写名称、租金、基本介绍，添加卧室、客厅等房间。
2. **按房间拍摄**：按引导录制视频或拍摄照片；为设施和重要局部补拍高清近照。
3. **上传与检查**：检查文件和画面质量；发现明显问题时提示重新选择素材或补拍。
4. **生成三维场景**：显示上传、排队、处理、完成或失败状态，保留任务进度入口。
5. **检查效果**：房东查看场景和质检清单，对照实拍，处理缺失、变形或模糊位置。
6. **补充细节**：放置设施与局部照片标记，填写公开说明或私人记录。
7. **确认并分享**：选择允许展示的房间，检查租客预览，生成看房链接。
8. **后续更新**：编辑草稿、补拍或更新记录；确认新版本后替换对外展示。

租客进入分享页后，看到房源介绍、房间列表、当前房间三维场景和公开细节。首版提供房间切换、预设观察点、视角控制和回到初始位置，移动范围限制在检查通过的区域内。

### 3.3 一次具体的看房体验

租客进入卧室，先观察床、衣柜和窗户的位置。点击空调标记后，打开型号近照和房东填写的说明；点击衣柜标记后查看内部收纳照片。房东在同一房间保存“下次检查空调排水”的私人备注，这条内容不出现在租客页面。

## 4. 首版功能和页面

### 4.1 五个主要页面

| 页面 | 主要内容与操作 | 空、等待或异常时的表现 |
| --- | --- | --- |
| 我的房源 | 房屋列表、出租状态、展示准备情况、创建入口 | 无房源时引导创建 |
| 拍摄与上传 | 房间列表、拍摄说明、素材选择、检查结果、处理状态 | 上传失败保留可恢复入口；状态未知时先查询 |
| 三维检查 | 场景预览、原始实拍对照、质检问题、补拍入口 | 场景加载失败显示原因；允许查看已上传的照片 |
| 房源编辑 | 租金与介绍、房间顺序、初始视角、细节标记、私人记录、租客预览 | 尚未检查完成的房间提示待处理 |
| 分享看房 | 已确认的房源信息、三维展示、公开照片和说明 | 设备不兼容时提供照片浏览；链接关闭后提示不可访问 |

基础能力包括房东登录和自己的房源管理。身份与房源归属校验覆盖页面、接口及三维资产读取。

### 4.2 “细节还原”的具体边界

| 细节类型 | 首版实现方式 | 说明 |
| --- | --- | --- |
| 布局与位置关系 | 三维场景 | 用于理解空间和可见外观 |
| 设施型号、收纳、插座 | 场景标记与高清实拍 | 原图中可读的信息才可作为依据 |
| 墙面污渍、破损等局部现状 | 近照、日期、位置和房东备注 | 与重建画面的伪影分开记录 |
| 房间或家具尺寸 | 房东录入实测值并注明来源 | 自动测量须另做尺度与精度验证 |
| 设施运行状态 | 房东填写和确认 | 图片中的外观不能证明设备正常工作 |

### 4.3 本版不纳入的范围

- 租金收缴、电子合同、交易支付、完整报修系统和多组织权限。
- 整屋自动拼接、跨房间连续行走、自动户型图和承诺精度的自动测量。
- 自动判断设备正常、结构安全、漏水原因或其他需要现场检查的结论。
- 用生成式内容补全未拍区域并作为真实房屋现状展示。
- 自行训练三维重建大模型、完整空间理解模型或多模型自动裁决系统。

## 5. 拍摄与三维重建方案

### 5.1 首版采集方式

建议先支持手机原生相机拍摄后上传，以普通视频作为首个验证入口，同时允许上传多张照片。设备、镜头、分辨率和具体拍摄时长在真实样本测试后确定。

拍摄引导要求画面清晰、移动缓慢、相邻视角有充分重叠，并尽量保持光照和场景稳定。窗边、门口和遮挡处需要专门检查；重要设施与局部情况另拍近照。镜子、玻璃、反光和弱纹理区域作为重点观察对象，不把它们的效果预设为可靠。[S2]

素材按用途分开：

- **重建素材**：提交给重建服务的视频或照片。
- **检查素材**：额外拍摄并预留，不参与重建，用于检查关键视角和细节。
- **展示近照**：经房东确认后供租客打开查看；可以选自检查素材，但保留其来源。

近照默认用于详情展示；是否适合混入重建输入，需要考虑视角重叠和拍摄条件，不能认为增加任意图片都能改善结果。

### 5.2 重建与查看候选

| 环节 | 本版候选 | 已知能力及未验证部分 |
| --- | --- | --- |
| 实拍三维重建 | Aholo 世界重建 | 官方支持多图、普通视频和 Insta360 素材做 3DGS 重建；本项目尚未实测房屋效果和费用 [S1] |
| 浏览器查看 | Aholo Viewer | 官方提供 3DGS、Mesh 渲染与分块加载能力；实际文件兼容、手机性能和交互需验证 [S3] |
| 设施与细节标记 | 应用层实现 | 首版由房东手动放置并确认，不依赖自动识别家具 |

Aholo 图片重建接口最低要求为 20 张图片。这是接口提交门槛，不是完整房屋的质量保证；房间实际需要的素材数量由覆盖情况和样本结果决定。[S1]

重建服务负责从实拍恢复场景表示，Viewer 负责加载和显示。Lux3D 等物体生成能力不进入首版真实房源重建流程。3DGS 主要支持新视角外观展示，几何精度和实测尺寸需要独立验证。[S6]

### 5.3 按房间推进

首版以单房间资产为单位。同一房源中的房间通过名称、缩略图和列表切换；独立重建的房间不默认共享原点、方向或尺度，也不据此计算跨房间距离。

先验证一个卧室，再扩展到一套房中的多个房间。跨房间配准、走廊与门洞连接，作为后续明确的技术增量。

## 6. 视觉模型辅助质检

### 6.1 职责与接入顺序

本版建议先接入一个支持多图对比的现成视觉模型，承担辅助质检和解释，不承担独立验收。供应商和具体版本待小样本比较后确定，不自行训练模型。

| 检查时点 | 模型任务 | 规则与人工职责 |
| --- | --- | --- |
| 重建前 | 发现可疑遮挡、过暗区域、重要设施缺少可辨近照 | 文件校验与清晰度检查优先使用普通算法；是否拍完整不能仅凭模型猜测 |
| 重建后 | 对照实拍与渲染图，提示明显缺失、变形、模糊或漂浮伪影 | 验证对照视角是否可靠，房东复核问题 |
| 发布前 | 汇总问题、证据和建议 | 系统检查发布条件，房东确认内容真实性 |

先实现拍摄质量提醒和重建问题清单，再根据验证结果决定是否自动拦截某些明确问题。

### 6.2 有证据的检查方式

1. 选择未参与重建的检查照片，覆盖主要观察点及重要局部。
2. 在三维场景中导出相应视角的画面，记录房间和场景版本。
3. 能获得可靠相机信息时匹配视角；仅能人工近似匹配时，限于可对照区域做定性判断，不计算或宣称严格的图像、几何精度。
4. 一并提供整体图和局部放大图，避免为了放大细节丢失位置关系。
5. 要求模型给出证据和不确定原因，禁止把“无法判断”默认为通过。

仅查看渲染截图不能证明真实还原。视觉模型的坐标定位是近似输出，细小或低质量图像也可能造成误判；模型建议的位置需要房东确认。[S4]

视频理解存在抽帧限制。例如 Gemini 官方文档说明，默认静态处理按每秒一帧采样，快速出现的细节可能被遗漏。因此首版细节验收采用选定的高清图片，整段视频分析作为辅助。[S5]

### 6.3 质检清单的内容

每条问题包含：房间、所属版本、位置描述、问题类别、影响、实拍与渲染证据、建议操作、无法判断的原因、房东处理结果。

问题类别至少分为“疑似重建问题”“实拍中的可见现状”“素材不足”和“无法比较”。模型提出的位置是待确认位置，不自动成为精确三维坐标。

示例：

> 卧室衣柜右侧：实拍中把手可辨，对应渲染区域明显模糊。建议补拍侧面近照。当前视角近似匹配，无法确定是遮挡还是重建细节缺失。影响：该处不适合靠三维画面查看，建议同时展示原图。

不采用未经校准的总分或模型自报置信度作为发布依据。允许的处理结果为：待复核、需要补拍、改用实拍说明、确认误报、已解决。

### 6.4 质检能力本身如何验证

选择包含正常画面和实际问题的房间样本，由人工标注问题类别和影响，再比较模型的漏检、误报、定位是否有用、建议是否可执行，并记录每房间调用时间和费用。

调整提示词使用开发样本；正式比较保留另一组样本，避免反复在同一组图片上调整后把结果当作泛化能力。影响最大的漏检单独列出，不用平均分掩盖。

## 7. 技术分工与发布规则

### 7.1 最小系统组成

| 部分 | 负责的内容 |
| --- | --- |
| 房东网页端 | 登录、房源与素材管理、处理进度、三维检查、标记编辑、确认发布 |
| 租客分享页 | 已发布内容、房间切换、三维交互、高清细节、照片回退 |
| 业务后端与异步任务 | 房源归属、任务记录、重建服务对接、结果检查、视觉模型调用、发布控制 |
| 私有文件存储与业务数据库 | 原始素材、场景文件、检查证据、近照、房源说明和私人记录 |
| 外部服务 | 首个重建候选和一个视觉模型；调用凭据由后端持有 |

部署方式与具体开发框架暂不锁定。先验证“真实素材 → 可加载资产 → 手机查看”的链路，再确定开发环境和服务配置。

### 7.2 房间处理与异常行为

房间处理过程为：待上传 → 素材检查 → 待重建 → 重建处理中 → 待复核 → 可加入展示。上传失败、重建失败、状态待确认、需要补拍、质检暂不可用都要有明确入口。

| 情况 | 预期行为 |
| --- | --- |
| 上传失败或中断 | 保留任务信息，重试失败部分；不触发重建 |
| 创建重建请求超时 | 标记状态待确认，先核对是否已创建任务，避免重复付费提交 |
| 服务报告成功但文件缺失、损坏或无法加载 | 保持待处理，不能作为三维房间发布 |
| 视觉模型超时或不可用 | 标记自动质检未完成，允许完成同一检查清单的人工复核；不显示 AI 通过 |
| 检查视角不对应 | 标记无法比较，补拍或人工确认可对照内容 |
| 场景重新重建 | 新建场景版本；旧标记和检查结论需要重新确认，防止位置漂移 |

默认一次素材版本发起一个重建任务。失败重试和补拍重建先展示新增费用或可用配额，不进行无上限自动重试。具体供应商能否查重或恢复未知任务，在接入时验证。[S1]

### 7.3 发布与访问

- 房东管理自己的完整档案；租客仅访问已发布版本中的公开信息、指定房间和公开标记。
- 原始采集素材、未发布版本和私人记录不通过分享页暴露；资产访问也校验授权，不能只在页面上隐藏。
- 发布前必须完成房东复核。场景不可加载等确定性错误必须修复；局部不足可以用实拍补充并说明，明显失真的房间不作为三维展示发布。
- 场景编辑和重建写入草稿，已发布内容继续使用此前确认的版本。再次发布时整体切换，避免模型和标记混用。
- 首版提供关闭分享链接的操作，关闭后阻止新的页面与资产授权访问；已经被他人保存的内容不在撤回能力范围内。

所有展示注明拍摄日期。房东录入的尺寸与设备状态标明来源，未拍到的区域不以生成内容替代真实记录。

## 8. 实施顺序和验收

以下为拟议阶段，不表示已经实施。本方案不预设“几天完成”或固定性能成绩，先通过样本确定可执行目标。

| 阶段 | 工作内容 | 阶段产物与进入下一步的条件 |
| --- | --- | --- |
| A：一个真实房间验证 | 拍摄、预留检查照片、执行一次受控重建、手机加载和人工检查 | 取得原始素材、实际资产、检查记录、耗时与费用；关键空间可辨，问题和设备表现可解释 |
| B：最小产品流程 | 房源、房间、素材、状态、三维查看、人工标记、房东复核 | 一个房间完成从上传到查看细节的全流程；异常有可恢复入口 |
| C：辅助质检 | 接入一个视觉模型，生成证据清单，完成与人工结果的比较 | 记录漏检、误报、成本和建议有效性；明确哪些结果需要人工判断 |
| D：一套房分享 | 多房间切换、公开与私人内容隔离、确认发布、关闭分享 | 在选定手机上完成远程看房；更新和撤回符合预期 |

### 8.1 首版验收清单

| 维度 | 通过依据 |
| --- | --- |
| 使用流程 | 房东可按引导完成样本房源；记录需要帮助或补拍的位置 |
| 资产可用性 | 已下载资产能够实际加载，不以接口成功代替文件验证 |
| 空间展示 | 对照检查照片，主要家具、门窗和位置关系可辨；拟展示房间没有未处理的明显失真 |
| 高清细节 | 关键设施和局部问题能打开对应实拍，来源、日期和说明清楚 |
| 质检可信度 | 每条问题有证据与处理结果；未知和未执行状态不会被标记为通过 |
| 手机体验 | 在事先选定的设备与网络上记录首屏时间、交互流畅度、内存和失败情况；正式门槛在 A 阶段后确定 |
| 权限与版本 | 租客看不到私人内容；草稿不改变线上版本；替换场景后标记重新确认 |
| 分享关闭 | 关闭后不能新获取受保护的展示内容或资产链接 |
| 异常与成本 | 上传中断、任务状态未知、外部服务失败均有明确结果；重试不会无提示重复创建付费任务 |

技术验收之外，需要让实际看房者尝试回答“床和衣柜如何摆放”“某项设施是什么”“哪个位置还需要线下确认”等问题，记录是否能找到证据。减少带看次数、提高出租效率属于后续业务指标，不在技术样本完成时直接宣称。

## 9. 待验证事项与成本

| 待确定事项 | 本版处理方式 |
| --- | --- |
| 首个样本、拍摄设备、目标手机和网络 | 在样本试验前记录；不阻碍本版方案交付 |
| 重建权限、价格、耗时、失败计费和资产使用条件 | 核验所用服务和实际账号，不把既有 Lux3D 报价套用到房屋重建 |
| 视觉模型供应商与版本 | 用相同人工标注样本比较效果、响应时间和费用后选择 |
| 单房间、单套房可接受费用 | 在首次付费任务前明确任务预算；按实际使用记录估算 |
| 手机可承受的资产大小和画质 | 通过真实资产测试确定压缩、分块加载或照片回退方案 |
| 原始素材与场景保留周期 | 实施前确定删除和保留规则，纳入存储成本 |

单套房成本按“各房间重建费用 + 补拍重建费用 + 视觉质检费用 + 存储和查看流量 + 人工复核时间”记录，区分首次建档的一次性开销和长期存储、访问的持续开销。

当前没有真实房屋任务费用、成功率、处理时长或本机性能数据。本方案完成后仍处于讨论阶段，未启动应用开发、付费重建、模型评测或外部发布。
